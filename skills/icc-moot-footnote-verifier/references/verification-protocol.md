# 脚注与引证核验协议

## 1. 目标

对书状中的每一条脚注，独立回答四个问题：

1. **来源是否真实存在？**
2. **引文是否确实出现在该来源中？**
3. **引文是否位于脚注标注的精确位置？**
4. **该引文是否支持正文中的那个命题？**

四个问题全部为“是”，才可标 `VERIFIED`。

本协议同时约束核验与校正。`icc-moot-memorial-writing` 起草、修改或定稿书状时，本协议自动执行；默认在核验后对已确认的引证错误做最小校正。只有用户明确要求只读时，才只报告不改稿。

## 2. 来源层级

| 层级 | 材料 | 核验用途 |
|---|---|---|
| 1 | 条约、Rome Statute、Elements of Crimes、Rules of Procedure and Evidence | 条文原文与要件 |
| 2 | 法院/法庭判决、决定、命令、咨询意见 | 规则解释与适用 |
| 3 | 赛题 Case File、Established Agenda、Order | 案件事实、争点与程序背景 |
| 4 | ILC/ICRC 官方评注、官方准备工作文件 | 条约解释背景 |
| 5 | 学术专著、论文、评注 | 仅作次级观点，不得替代一手权威 |
| 6 | 项目写作思路、旧稿、检索记录、AI 摘要 | 仅作线索，**不得作为引文最终来源** |

引用层级 5 时，必须明确标注其学术观点属性；引用层级 6 时，必须回到其指向的一手来源。

## 3. Citation ledger 字段

| 字段 | 必填 | 说明 |
|---|---|---|
| `fn_id` | 是 | `FN-001` 起 |
| `location` | 是 | 章节、段号；DOCX 可加页码 |
| `proposition` | 是 | 该脚注支持的正文命题，一句话 |
| `citation_text` | 是 | 脚注完整文本 |
| `source_type` | 是 | Treaty / Judgment / Decision / Order / Case File / Commentary / Other |
| `title` | 是 | 条约或文书名称 |
| `document_number` | 条件 | 案件文书号、条约编号、官方文件号；无编号则写 `N/A` |
| `court_chamber` | 条件 | 法院、分庭；条约不需要 |
| `date` | 是 | 通过/裁判/文件日期 |
| `pinpoint` | 是 | `art. 8(2)(a)(iv)` / `para. 314` / `p. 17` |
| `exact_quote` | 是 | 从原文逐字复制的句子；可多句，但每句单独标注 |
| `local_path` | 条件 | 本地原件路径；无则写 `MISSING` |
| `sha256` | 条件 | 终稿核验时记录原件哈希 |
| `official_url` | 条件 | 官方来源 URL；无则写 `MISSING` |
| `read_scope` | 是 | `full-text` / `abstract-only` / `metadata-only` / `index-snippet` |
| `verification_status` | 是 | 见第 6 节 |
| `notes` | 否 | 例外、翻译问题、需人工判断处 |

## 4. 不同来源的核验方法

### 4.1 条约与规约

- 核对条约全称、缔约日期、生效日期、UNTS 卷页（如适用）。
- 核对条号、款号、项号；注意英文编号控制。
- 引文必须与官方英文文本逐字一致。
- 若引用的是中文译本，必须同时核对英文原文；中文译本只能作为工作翻译。

### 4.2 判决、决定、命令

- 核对案件名、文书类型（Judgment / Decision / Order / Reasons）、文书号、分庭、日期。
- 核对 pinpoint 是段落号还是页码；不要把页码当段号。
- 核对引文是否在**该段**，而不是同一判决的其他段落。
- 注意单独意见、反对意见、附随意见；不要把单独意见写成多数意见。
- 注意程序阶段：确认指控决定、审判判决、上诉判决的权威层级不同。
- 若引用的是脚注中的材料，标明 `cited in` 并尽量回到原始来源。

### 4.3 赛题 Case File

- 核对赛题段落号；赛题是虚构的，不得当作真实新闻或现实案件检索。
- 区分“Prosecution’s presentation of evidence”“Defense submission”“Pre-Trial Chamber finding”“Order”四种陈述主体。
- 不得把当事方主张写成法庭认定；不得把裁决主文写成裁判理由。

### 4.4 学术评注

- 核对作者/机构、篇名、书名、期刊、年份、卷期、页码。
- 标明其相对于条约/判例的次级性质。
- 不得用学术观点替代条约原文或判例 holding。

## 5. 精确引文与 pinpoint

### 5.1 引文比对

允许的机械规范化：

- 弯引号/直引号互换
- 连续空白折叠
- 换行连字符与软连字符
- 大小写不敏感（仅用于初筛，最终仍按原文核对）
- Unicode NFKC 规范化

不允许：

- 改动词形、增删否定词、替换主体
- 把两段不同的话拼成一段引文
- 用省略号掩盖关键限定语
- 把转述当成直接引文

### 5.2 Pinpoint

- 引文必须出现在标注的 `para.` / `page` / `article`。
- 若引文跨两段，标注 `paras X–Y`，并分别核对每段。
- 若引文在脚注而非正文，标注 `para. X, fn. Y`。
- 若只找到“相似句”而找不到原句，标 `QUOTE-NOT-FOUND`，不要自行改写脚注。

## 6. 状态定义

| 状态 | 判定条件 | 处理 |
|---|---|---|
| `VERIFIED` | 来源存在 + 引文逐字存在 + pinpoint 正确 + 命题支持 | 通过 |
| `PARTIAL` | 来源存在、引文存在，但命题支持或 pinpoint 仍需人工确认；或只读到摘要/元数据 | 黄，需复核 |
| `WRONG-PINPOINT` | 引文存在，但不在标注位置 | 红，修正 pinpoint 或引文 |
| `QUOTE-NOT-FOUND` | 在指定来源的全文/可检索文本中找不到引文 | 红，换来源或改写命题 |
| `MISATTRIBUTED` | 引文存在，但属于另一案件/文书/段落 | 红，修正来源 |
| `NOT-SUPPORTED` | 引文存在，但不支持正文命题 | 红，改写命题或换引文 |
| `MISSING-SOURCE` | 无本地原件且无官方 URL | 红，补源或删引 |
| `MISSING-DEFINITION` | 脚注引用存在但脚注文本缺失 | 红，补定义 |
| `UNVERIFIED` | 尚未核验 | 灰，不计入通过 |

## 7. 默认模式、抽样与全量

### `inventory`

- 提取全部脚注。
- 检查：空脚注、缺号、重号、重复引文、明显无来源、明显缺 pinpoint。
- 不做逐条原文比对。
- 用于大纲、局部段落和章节初稿；默认修正机械与结构问题。

### `sample`

- 按来源类型分层：条约、判决、Case File、学术评注各抽若干。
- 必抽高风险项：新来源、二手来源、AI 辅助段落、无本地文件、引文超过两行、同一脚注含多个来源。
- 抽样比例约 20%，但高风险项全查。
- 只用于完整工作稿的中间审阅或用户明确要求抽查，不用于最终提交稿。

### `full`

- 100% 逐条核验。
- 任何完整交付稿、终稿或声称 `submission-ready` 的版本必须 `full`。
- 核验后如正文或脚注有实质修改，受影响条目重新核验。

默认映射：局部草稿 → `inventory`；完整书状 → `full`；`sample` 仅在时间受限或用户要求抽查时使用。

## 8. 终稿审计顺序

1. 锁定最终 DOCX/Markdown 版本与哈希。
2. 提取全部脚注，确认无空脚注、无缺号、无重复。
3. 逐条核验来源、引文、pinpoint、命题。
4. 检查 `ibid.`、短引、交叉引用是否指向正确来源。
5. 检查 Index of Authorities 与脚注双向对应。
6. 检查引证体系是否全篇一致。
7. 检查 AI 虚构风险：所有 `QUOTE-NOT-FOUND` / `MISSING-SOURCE` 必须清零或明确标注。
8. 对已确认的引证错误做最小校正，并填写脚注校正记录。
9. 重新提取并复核受影响的脚注，更新文件哈希。
10. 输出报告；只有全部红项解决，才可写 `submission-ready`。

## 9. 常见失败模式

- 把写作思路中的引文块直接当原文。
- 把案件名 + 段号当作完整引证，缺文书号/分庭/日期。
- 把判决页码当作段落号。
- 把单独意见写成多数意见。
- 把当事方主张写成法庭认定。
- 引文只支持“存在某个规则”，却用来证明“本案适用该规则”。
- 一个脚注堆五个来源，但没有任何一个来源支持该句。
- 用 `ibid.` 指代隔了多条脚注的来源。
- 引文来自 AI 摘要，原文其实没有这句话。
- 把“校正”做成凭印象补来源、补页码或补引文。
- 为了让报告好看而删除不利引证，或把 `NOT-SUPPORTED` 直接改成一句更弱的空话。

## 10. 效率原则

- 在 `icc-moot-memorial-writing` 书状工作流中默认执行；独立使用时按用户请求执行。
- 先 `inventory`，再决定是否需要 `sample`/`full`。
- 用文件哈希缓存已核验结果；文件未变则不重复全查。
- 同一来源只读一次，建立来源卡片，供多条脚注复用。
- 不在核验阶段做无边界检索；只查当前脚注需要的来源。
- 校正优先处理机械项和已确认的归属错误；不能确认的缺口留给作者，不猜测。
- 修改后只复审受影响条目，不重复全库核验；终稿仍须 `full`。

## 11. 校正协议

### 11.1 校正的前提

- 已打开原文或官方来源，能够确认正确值。
- 修改不改变实体立场、论证结构或请求事项。
- 修改范围限于脚注、引证和使本次修改成立的依赖项。

### 11.2 允许的校正

| 类型 | 示例 |
|---|---|
| 文书身份 | 案件名、文书类型、文书号、分庭、日期 |
| 定位 | 段号、页码、条号、款号、项号 |
| 引证外观 | 统一体例、缩写、标点、大小写、斜体 |
| 回指 | `ibid.`、短引、交叉引用、脚注编号 |
| 结构 | 脚注锚点、空脚注、缺号、重号、重复定义 |
| 索引 | Index of Authorities 与脚注的双向对应 |

### 11.3 禁止的校正

- 补写来源、引文、页码、段号、URL 或作者
- 用搜索摘要、二手笔记或语言模型输出替代原文
- 删除不利引证、不利事实或不利判决
- 改变实体论证、请求事项或角色立场
- 把 `QUOTE-NOT-FOUND` / `MISSING-SOURCE` 用猜测掩盖

### 11.4 校正记录字段

| 字段 | 说明 |
|---|---|
| `fn_id` | 受影响的脚注 |
| `field` | 修改字段 |
| `before` | 修改前内容 |
| `after` | 修改后内容 |
| `basis` | 原文文件、页码/段号或官方 URL |
| `status_after` | 重新核验后的状态 |

校正后必须重新提取脚注、复核受影响条目、更新报告和文件哈希。未能校正的红项在报告中保留，并写明最小修复动作。
